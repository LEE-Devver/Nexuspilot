# NexusPilot Agent Event Protocol

## Status

Phase 9A defines the persistent, metadata-only Agent Event Protocol and host registry.

Phase 9B adds the explicit opt-in Desktop transport. The listener is disabled by default, binds only to `127.0.0.1` on an ephemeral port, requires an in-memory Bearer capability token, validates the strict shared event schema, enforces a 16 KiB JSON body limit, and rate-limits accepted attempts to 120 requests/minute. External provider hooks/adapters are not bundled yet; providers must still opt in and send protocol events deliberately.

## Goal

Allow Claude Code, Codex, and future local agent providers to voluntarily register their lifecycle with NexusPilot so the Agent Monitor can show externally-started workers without silently scanning every process on the machine.

```text
Claude Code / Codex / provider adapter
            |
            | opt-in metadata events
            v
      Agent Event Protocol
            |
            v
   AgentEventService
            |
            v
SQLite current registry + bounded event history
            |
            v
      Agent Monitor
```

## Payload

The canonical event input contains only monitor metadata:

```text
agentId
parentAgentId?
provider              codex | claude_code
workspaceId
clientId?
sessionId?
label
eventType
state?
currentActivity?
toolName?
ttlSeconds?
```

Supported event types:

```text
registered
started
updated
heartbeat
spawned
tool_started
tool_completed
completed
failed
disconnected
```

Supported states:

```text
starting
running
completed
exited
failed
cancelled
stopped
timed_out
termination_unverified
```

The protocol intentionally has **no prompt body, result body, command arguments, stdout, stderr, credentials, tokens, or arbitrary metadata object**.

## Time and lease rules

Provider timestamps are not trusted as canonical monitor time in Phase 9A.

NexusPilot records the host receipt time and uses it for:

- event timestamp,
- observation updatedAt,
- startedAt for start/spawn events,
- TTL expiry.

Default active lease:

```text
120 seconds
```

Accepted provider TTL range:

```text
30 .. 3600 seconds
```

Terminal observations are retained for 15 minutes so completed/failed agents remain visible briefly in topology/timeline.

Event history is bounded to 24 hours by the service cleanup policy.

## Persistence

Current observations:

```text
agent_external_observations
```

Bounded history:

```text
agent_external_events
```

The current registry stores only the latest safe observation for each stable `agentId`.

## Parent/child relationships

A child provider may send:

```text
agentId: child-1
parentAgentId: parent-1
```

NexusPilot maps these to monitor IDs:

```text
external:parent-1
    |
    +-- external:child-1
```

Topology resolution is order-independent: a child may be observed before its parent and the relationship is resolved from the final snapshot.

## Security boundary

Phase 9A does not change public MCP ownership rules.

Remote MCP callers still cannot inspect another session's private result content.

The local Desktop Monitor receives only metadata projections.

Phase 9B transport invariants:

1. loopback-only on `127.0.0.1`,
2. explicit user opt-in and disabled-by-default persistence,
3. authentication capability/token generated by NexusPilot and kept in memory only,
4. bounded 16 KiB request body,
5. strict JSON schema / no arbitrary metadata,
6. bounded host-local rate limiting,
7. provider/event/state/workspace field validation before ingestion,
8. no silent OS-wide process discovery,
9. no prompt/result/output bodies,
10. listener/token teardown on disable and Desktop shutdown.

## External provider integration direction

Preferred integration is active registration:

```text
external provider
   -> register/start
   -> heartbeat/update/tool events
   -> complete/fail/disconnect
```

rather than passive process scraping.

## Phase 9C hook adapter

NexusPilot now ships `scripts/agent-event-hook.mjs`, a fail-open hook adapter for local Codex and Claude Code lifecycle hooks.

The adapter:

- reads the provider hook JSON from stdin,
- maps only lifecycle metadata into the shared Agent Event Protocol,
- deliberately drops prompt text, tool input/output, transcripts, assistant messages, and arbitrary provider fields,
- derives a stable external workspace ID from `cwd` unless `NEXUSPILOT_WORKSPACE_ID` is provided,
- preserves root/subagent topology when `agent_id` is available,
- sends events only when both `NEXUSPILOT_AGENT_EVENT_ENDPOINT` and `NEXUSPILOT_AGENT_EVENT_TOKEN` are explicitly present,
- fails open when NexusPilot is stopped or the ingress cannot be reached, so observability never blocks the provider workflow.

Supported hook mappings:

```text
SessionStart     -> started
SessionEnd       -> completed
SubagentStart    -> spawned
SubagentStop     -> completed
PreToolUse       -> tool_started
PostToolUse      -> tool_completed
UserPromptSubmit -> heartbeat
Stop/Interrupt   -> updated (non-terminal)
```

For Codex, configure command hooks for the lifecycle events you want to observe and run:

```text
node /absolute/path/to/NexusPilot/scripts/agent-event-hook.mjs --provider=codex
```

Codex command hooks receive a JSON object on stdin with fields such as `session_id`, `cwd`, `hook_event_name`, `agent_id`, and `tool_name`; the adapter intentionally ignores sensitive payload fields. Configure the same command shape for Claude Code with `--provider=claude_code` when using its lifecycle hooks.

The ingress endpoint/token remain app-session capabilities. Copy them from NexusPilot Settings into the environment of the provider process; they are not persisted by the adapter.

Future packaging may add one-click hook installation, but it must preserve explicit user opt-in and must not persist the ephemeral ingress token.

## Removal / evolution rule

The protocol should be versioned before exposing a stable external transport.

Do not add arbitrary provider-specific fields directly to the shared event body. Extend through explicit versioned fields only when a real consumer exists.
